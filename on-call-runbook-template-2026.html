On-Call Runbook Template for Small DevOps Teams

Updated 2026 - 12 min read - Template included

#DevOps#OnCall#Runbook#Operations

When the pager goes off at 3am, you need a runbook that tells you exactly what to do. Not a 200-page document. A one-page runbook that gets you from "alert" to "resolved" fast.

Section 1: When You Get Paged

  1. Acknowledge the page within 5 minutes.
  2. Check the alert details: What service? What metric?
  3. Check the dashboard: Real issue or fluke?
  4. Check recent changes: Deployments in last 2 hours?
  5. Determine severity: SEV1, SEV2, or SEV3.
  6. Create an incident channel if SEV1 or SEV2.

Section 2: Quick Fixes by Symptom

Service is Down (HTTP 502/503)

  1. Check if process is running
  2. Check recent deployments
  3. Roll back if needed
  4. Check resource limits
  5. Check logs
  6. Restart if needed

High Error Rate (5xx)

  1. Check error logs for patterns
  2. Check database connections
  3. Check external API status pages
  4. Check for recent config changes
  5. Roll back if bad deploy

High Latency

  1. Check CPU/memory usage
  2. Check database slow queries
  3. Check network/DNS
  4. Check queue depth
  5. Scale up if resource-constrained

Database Issues

  1. Check connection pool
  2. Check slow queries
  3. Check disk space
  4. Check replication lag
  5. Check for locks
  6. Kill long-running queries if blocking

Disk Space Full

  1. Check disk usage
  2. Find large files
  3. Check log files
  4. Rotate/compress old logs
  5. Clean up temp files

Section 5: Post-Incident

  1. Schedule post-mortem within 48h
  2. Write timeline of events
  3. Identify root cause and contributing factors
  4. Create action items with owners
  5. Update this runbook with learnings
Pro tip: Keep this runbook next to your pager. Print it. Pin it. Use it.
